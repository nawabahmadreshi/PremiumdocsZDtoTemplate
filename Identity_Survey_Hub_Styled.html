Identity Survey Hub User Guide

Aquera Documentation

Overview

Identity Survey Hub is a structured onboarding and discovery platform that replaces meeting-heavy application intake processes with automated, trackable workflows purpose-built for IGA and IDP integrations. It enables application owners, IAM teams, and stakeholders to collaboratively provide validated onboarding data—covering ownership, access models, authentication methods, provisioning requirements, and compliance attributes—through configurable questionnaires with delegation, SLAs, and escalation controls. By centralizing and standardizing application discovery, Identity Survey Hub accelerates IGA and SSO onboarding, improves data completeness, reduces dependency on manual coordination, and creates a reusable, governance-ready application inventory.

Key Features

The following are the key features of the Identity Survey Hub:

  • Simplified Asset Discovery
    • Questionnaire-driven approach for efficient asset identification and data collection.
    • Discovered assets are cataloged and enriched with critical metadata.
    • Creates a comprehensive, searchable asset inventory for effective governance.
  • Automated Onboarding Process
    • Automated workflows for onboarding assets into the IGA platform.
    • Eliminates the need for lengthy discovery meetings.
    • Reduces manual intervention and accelerates asset onboarding.
  • Progress Monitoring
    • Track which assets are complete, delayed, or in progress.
    • Allows setting multiple reminders.
    • Enforce deadlines by involving managers when timelines slip.
  • Parallel Onboarding
    • Onboard hundreds of apps simultaneously instead of sequentially.
  • Configurable Settings Module
    • Organization Management: Maintain essential organizational data such as name, address, contact details, and identifiers.
    • User Management: Add, edit, and list user accounts for streamlined access control and administration.
    • Template Management: Create and manage customizable email templates for automated notifications.
    • Operational Efficiency: Improve workflow efficiency and ensure timely communication through configurable settings and notifications.
  • Structured Identity Survey Lifecycle
    • Automated Survey Distribution: Enables admins to efficiently send surveys to recipients for initial data collection.
    • Data Validation & Enrichment: Ensures that the collected information is accurate and complete, and facilitates the collection of additional data during the staging phase.
    • Comprehensive Discovery Process: Facilitates deeper data gathering through extended questionnaires for detailed asset profiling.
    • Centralized Asset Inventory: Maintains a validated and compliant catalog of assets for ongoing tracking and governance.
    • End-to-End Workflow Management: Streamlines the entire lifecycle from survey initiation to inventory integration, enhancing data reliability and operational transparency.
  • File Collection
    • File-Based Data Integration: Allows importing user data from disconnected assets through file uploads or SFTP.
    • File Management and Scheduling: Supports scheduling uploads, reminder and escalation emails, and auditing file uploads.
    • SFTP and IGA configuration: Enables SFTP setup for file processing and global IGA settings for correlation checks during uploads.
  • Centralized Questionnaire Management
    • Allows creation and management of individual questionnaires.
    • Supports customization to meet the specific needs of each phase in the asset discovery and onboarding lifecycle.
    • Consolidates all questionnaire templates in a single, centralized location for streamlined access and management.
  • Access Graph Analysis
    • Supports uploading and analyzing identity and access data for individual assets.
    • Search users, groups, roles, and entitlements across multiple applications.
    • Displays data in an interactive tree graph format for intuitive visualization.
  • Task Management
    • Provides a centralized workspace for tracking all activities, from surveys to onboarding, assigned to users.
  • Activity Logs
    • Provides a centralized workspace for tracking system events, user actions, and application transactions.

Asset Definition

An asset refers to any application, system, platform, or resource used by the organization that must be tracked, governed, or managed. This includes, but is not limited to:

  • SaaS applications
  • On-premises enterprise applications
  • Cloud platforms and resources
  • Databases, servers, and virtual infrastructure
  • Shared accounts and non-human identities

Each asset entry in the catalog contains standardized metadata to enable classification, governance, and lifecycle management.

IGA Configuration

The IGA Configuration tab allows administrators to correlate data uploaded in the application with the list of users obtained from a file downloaded from an Identity Governance and Administration (IGA) system, such as SailPoint or Okta.

It enables uploading an IGA file and configuring a schedule for file uploads. It also provides an option to enable correlation checks, which automatically compare data during each file upload.

When the correlation check is enabled, a report showing the number of mismatched records is generated during each data file upload.

Enable Correlation Checks and Set Upload Schedule

Perform the following steps to enable the correlation check and set the IGA file upload schedule:

  1. Navigate to the IGA Configuration tab.
  2. Click Edit Configuration. The IGA Global Configuration pop-up window appears.
  3. In the IGA Global Configuration pop-up window, enable the Global Correlation Check toggle. 
    Note: If this setting is disabled, the correlation check will not be performed during the data file uploads.
  4. Set the following configuration under the Schedule section:
    • File Upload Frequency: Specifies how often the IGA file must be uploaded. The dropdown options are: Weekly, Monthly, Quarterly, and Yearly.
    • Next File Upload Date: The due date for the next IGA file upload. For example, if the File Upload Frequency is set to Weekly and the Next File Upload Date is 16-January-2026 (a Friday), the file upload will be due every Friday.
    • Timezone: The timezone that should be followed for the file upload schedule.
  5. Click Save Configuration to apply your settings.

An email reminder for the IGA file upload is sent to the corresponding asset owners and admin users on the due date.

Upload IGA File

You must upload the IGA file in one of the following formats: CSV, XLS, or XLSX. The file must include a column that serves as the correlation attribute, which is used to match user data during data file uploads.

File Retention Settings

The File Retention Settings tab allows administrators to configure how long uploaded files and their history are retained. Once the defined retention period expires, both the uploaded file and its upload history records are automatically deleted.

Perform the following steps to configure file retention settings:

  1. Navigate to the File Retention Settings tab.
  2. By default, the File History Retention toggle is enabled. The Retention Duration field is visible only when this toggle is enabled.
  3. Select the desired duration for retaining file upload history in the Retention Duration field. Available retention duration options are:
    • Last 6 Months
    • Last 1 Year
    • Last 2 Years
  4. The retention settings are saved automatically as soon as you select a duration.

Upload history records and files older than the selected duration (calculated from the current date) will be deleted weekly.

  • Deletion is scheduled to run every Sunday.
  • For example, if Last 6 Months is selected, all upload history records and associated files older than six months from the current date will be deleted weekly.

Note: If a file was not uploaded on the scheduled date, the file history will show a record with the status Missed. These records will not be deleted and will remain in history.

Primary Interfaces

  • Tasks: This tab presents a centralized interface for creating, tracking, and managing all asset-related tasks with ease and efficiency.

Lifecycle of the Asset

The Asset Lifecycle consists of several key stages that represent the journey of an IT asset from identification to full cataloging:

  1. Survey: The initial phase involves administrators sending simple questionnaires to asset owners or relevant stakeholders to collect basic information about IT assets.
  2. Staging: In this intermediate phase, the collected survey data undergoes validation and enrichment. This ensures the information is accurate and comprehensive, facilitating deeper discovery and preparation for subsequent onboarding activities.
  3. Discovery: This phase involves a collection of detailed data about IT assets through extended questionnaires. The gathered information is then validated and enhanced as necessary to support the final onboarding process.
  4. Inventory: The final stage involves transferring fully validated and enriched asset data into the official asset catalog and onboarding it to the IGA/SSO platform. This ensures accurate tracking, compliance, and effective management of IT assets throughout their lifecycle.

Staging

The Staging is the intermediate phase where IT assets are cataloged using surveys and structured questionnaires to build a reliable inventory foundation. During this stage, assets are primarily populated from survey responses, although a few can be added manually or imported directly from IGA applications. The collected information is then validated and enriched to create a comprehensive asset inventory that supports subsequent discovery and onboarding activities.

Assets are grouped into collection groups based on asset types. Administrators create and configure these groups, while Asset Owners and Collaborators supply the required information. This role-based coordination ensures a reliable foundation for the organization's IT asset catalog, supporting identity and access management and setting the stage for further discovery and onboarding activities.

Collection

A Collection groups related assets together, making it easier for administrators to manage the inventory by handling one set at a time. This approach enables them to validate information, send reminders, or escalate issues without being overwhelmed by the entire catalog. Because each Collection is clearly defined, administrators, asset owners, and collaborators know exactly which assets require attention and understand their status in the process. Once every asset in a collection has been reviewed and approved, those assets can move forward to the next phase.

File Collection

Identity Survey Hub enables the system to collect and display identity data from a disconnected application using a file-based approach. Disconnected applications are those that do not provide APIs for direct integration with other applications, databases, or services. In such scenarios, files act as the primary source of identity data.

This section explains how administrators manage files using the File Collection module. It describes the procedures for scheduling file uploads, configuring reminder and escalation emails, setting up audit file uploads, and configuring SFTP connections. You can also configure the IGA global settings to determine whether a correlation check is performed against an IGA file during file uploads. This approach helps keep data up to date and supports the overall integrity of the application.

In the file collection workflow, administrators must add file-based applications, after which scheduled groups are created. The added applications can then be selected and assigned to the appropriate scheduled group for file upload processing.

For example, if the FTP Server Directory Path is /Aquera/Files and the folder path specified in this tenant attribute is /Userdata, the application will read the data files from /Aquera/Files/Userdata on the SFTP server.
  • Validate Headers: Select to validate the header row in the uploaded file. When selected, the AI assistant automatically generates mappings for all columns in the file.
    If you want to map only specific columns instead of all columns, do not select this checkbox. In this case, data will be retrieved only from the mapped columns, and any data in the remaining columns will be ignored.
    Note: If your file does not contain a header row, do not select this checkbox.
  • Validate Role IDs in User File: Select to validate the roles assigned to users in the users file against the members listed in the roles file. If a user is assigned a specific role in the users file but is not listed as a member of that role in the roles file, the system will report an error during the file upload process.   • Is Using SFTP Server: Select this checkbox if your Storage Type is set to SFTP Storage.
  • Match the Users Against the Uploaded IGA File: Select to match users in the uploaded data file against the list of users in the uploaded IGA file.
